# متجر «لمسة» — متجر إلكتروني عربي كامل

متجر إلكتروني عربي بواجهة RTL كاملة، مبني بـ **PHP 8 + MySQL/MariaDB** دون أي إطار عمل أو مكتبات خارجية.
يعمل مباشرة داخل **XAMPP** بعد نسخ الملفات واستيراد ملف قاعدة بيانات واحد.

---

## 1. المتطلبات

| المتطلب | الإصدار |
|---|---|
| XAMPP | أي إصدار حديث يحتوي PHP 8.0 أو أحدث |
| PHP | 8.0+ مع الإضافات `pdo_mysql` و `mbstring` و `fileinfo` |
| MySQL / MariaDB | 10.4+ أو MySQL 5.7+ |
| المتصفح | أي متصفح حديث |

> إضافتا `pdo_mysql` و `mbstring` مفعّلتان افتراضياً في XAMPP.

---

## 2. التركيب خطوة بخطوة

### الخطوة 1: نسخ ملفات المشروع

انسخ **محتويات هذا المجلد** إلى داخل `htdocs` في XAMPP، مثلاً:

```
C:\xampp\htdocs\web1\
```

> يمكنك تسمية المجلد كما تشاء (`web1`، `lamsa`، `shop`...). الموقع يكتشف مساره تلقائياً.

### الخطوة 2: تشغيل Apache و MySQL

افتح **XAMPP Control Panel** ثم اضغط **Start** أمام:

- Apache
- MySQL

تأكد أن المنفذين `80` و `3306` غير مستخدمين من برنامج آخر.

### الخطوة 3: استيراد قاعدة البيانات

1. افتح [http://localhost/phpmyadmin](http://localhost/phpmyadmin)
2. من الشريط العلوي اختر تبويب **Import** (استيراد).
3. اضغط **Choose File** واختر ملف:

   ```
   database.example.sql
   ```

   > ملف `database.sql` غير مضمّن في المستودع لأنه يحتوي بيانات حسابك الحقيقية. الملف المثال يحتوي نفس الجداول والمنتجات التجريبية مع حساب مدير تجريبي.

4. اترك جميع الخيارات على وضعها الافتراضي واضغط **Go** (تنفيذ).

سيُنشئ الملف قاعدة البيانات `lamsa_store` تلقائياً مع كل الجداول والبيانات التجريبية.
**لا حاجة لإنشاء قاعدة البيانات يدوياً.**

> إذا ظهرت رسالة نجاح خضراء فهذا يعني أن كل شيء تم بنجاح.

### الخطوة 4: فتح الموقع

افتح المتصفح على:

```
http://localhost/web1/
```

(استبدل `web1` باسم المجلد الذي اخترته.)

## 3. حسابات الدخول التجريبية

هذه بيانات **`database.example.sql`** فقط (لتثبيت جديد). نسختك المحلية الحالية تحتفظ بحساب المدير `admin@lamsa.com` وكلمة المرور التي غيّرتها.

| النوع | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| **مدير المتجر** | `admin@example.com` | `ChangeMe!2026` (غيّرها فوراً) |
| **عميل تجريبي** | `ahmad@example.com` | `Test@1234` |

- لوحة الإدارة: `http://localhost/web1/admin/`
- لا تُعرض بيانات الدخول على صفحة تسجيل الدخول إطلاقاً.
- لتغيير كلمة مرور المدير: من داخل لوحة التحكم بعد الدخول، أو عبر توليد hash جديد بـ `password_hash()` وتحديثه في قاعدة البيانات.

> **مهم:** احتفظ بكلمة مرور المدير في مكان آمن، ولا تنشرها في ملفات الموقع أو مستودعات Git.

## 4. إعدادات قاعدة البيانات

الإعدادات موجودة في ملف واحد فقط:

```
config/config.php
```

القيم الافتراضية المتوافقة مع XAMPP:

```php
define('DB_HOST', '127.0.0.1');
define('DB_PORT', '3306');
define('DB_NAME', 'lamsa_store');
define('DB_USER', 'root');
define('DB_PASS', '');
```

إذا كانت قاعدة بياناتك تستخدم كلمة مرور أو منفذاً مختلفاً، عدّل القيم مباشرة.
ويمكن أيضاً تجاوزها عبر متغيرات البيئة:

```
LAMSA_DB_HOST
LAMSA_DB_PORT
LAMSA_DB_NAME
LAMSA_DB_USER
LAMSA_DB_PASS
```

### إعدادات المتجر الأخرى (في نفس الملف)

```php
define('SITE_NAME', 'لمسة');
define('CURRENCY', 'د.أ');
define('SHIPPING_FEE', 2.00);          // رسوم التوصيل
define('FREE_SHIPPING_FROM', 50.00);   // الشحن مجاني فوق هذا المبلغ
```

## 5. المزايا

### واجهة المتجر
- تصميم عربي RTL متكامل بخط Cairo وهوية بصرية موحّدة.
- صفحة رئيسية بأقسام، منتجات مميزة، عروض، وبحث فوري.
- تصفّح حسب القسم، البحث، الترتيب (الأحدث/السعر/الخصم)، وترقيم الصفحات.
- صفحة منتج بتفاصيل كاملة، صور، خصومات، ومؤشر للمخزون.
- سلة تسوق محفوظة في الجلسة مع تعديل الكميات وحذف المنتجات.
- إتمام الطلب مع بيانات التوصيل والدفع عند الاستلام، والتحقق من المخزون داخل معاملة (Transaction).
- حساب العميل: إنشاء حساب، تسجيل دخول/خروج، تعديل البيانات، تغيير كلمة المرور، وسجل الطلبات.
- تنبيهات (Flash messages) وصفحة 404 مخصصة.

### لوحة الإدارة
- لوحة إحصائيات: المبيعات، الطلبات، العملاء، والمنتجات.
- إدارة المنتجات: إضافة، تعديل، حذف، إظهار/إخفاء، ورفع صورة.
- إدارة الطلبات: عرض التفاصيل وتحديث الحالة (قيد المراجعة → قيد التجهيز → تم الشحن → تم التوصيل / ملغي).
- إلغاء الطلب يعيد الكميات تلقائياً إلى المخزون.
- بحث وفلاتر للمنتجات والطلبات.

### الأمان
- كلمات المرور مشفّرة بـ `password_hash` / `password_verify`.
- حماية CSRF على جميع نماذج POST.
- استعلامات مُهيّأة (Prepared Statements) تمنع حقن SQL.
- تهريب المخرجات عبر `htmlspecialchars` لمنع XSS.
- حماية الصفحات الإدارية والتحقق من ملكية الطلبات.
- تحديد محاولات تسجيل الدخول (5 محاولات خاطئة ثم قفل مؤقت).
- التحقق من نوع الصور المرفوعة فعلياً عبر `finfo` و `getimagesize`، ومنع رفع SVG أو ملفات PHP.
- ملفات `.htaccess` تمنع الوصول إلى `config/` و `includes/` ومنع تنفيذ السكربتات داخل `uploads/`.

## 8. حل المشكلات الشائعة

| المشكلة | الحل |
|---|---|
| **خطأ في الاتصال بقاعدة البيانات** | تأكد أن MySQL يعمل في XAMPP، وأن اسم القاعدة `lamsa_store` وبيانات الدخول صحيحة في `config/config.php`. |
| **صفحة بيضاء أو خطأ 500** | تأكد أن PHP 8 يعمل، وأن امتدادي `pdo_mysql` و `mbstring` مفعّلان في `php.ini`. |
| **الموقع يعمل على مسار خاطئ** | الموقع يكتشف `BASE_URL` تلقائياً؛ تأكد أنك فتحت الرابط داخل `htdocs` وليس عبر `file://`. |
| **الصور لا تظهر** | تأكد من وجود مجلد `assets/img/products/` وأن صلاحيات `uploads/products/` تسمح بالكتابة. |
| **تعذّر رفع الصور** | تحقق من صلاحيات مجلد `uploads/` ومن حجم الصورة (الحد الأقصى 3 ميغابايت) وصيغتها (JPG/PNG/WEBP/GIF). |
| **«محاولات دخول كثيرة»** | انتظر بضع دقائق أو أعد تشغيل الجلسة بمسح الكوكيز، فالحماية مؤقتة. |
| **ملفات `.htaccess` لا تعمل** | تأكد أن `AllowOverride All` مفعّل لمجلد `htdocs` في إعدادات Apache (وهو الافتراضي في XAMPP). |

> **مهم:** GitHub Pages تستضيف ملفات ثابتة فقط (HTML/CSS/JS) ولا تشغّل PHP أو MySQL. لذلك نسخة العرض تتيح تصفّح الواجهات فقط، بينما النسخة الكاملة على InfinityFree تعمل بقاعدة بيانات MySQL حقيقية.

### إعداد الاستضافة (InfinityFree)

- الدومين: `lamsastore.42web.io`
- مجلد الموقع: `htdocs/`
- قاعدة البيانات: تُضبط في `config/config.local.php` (مستثنى من Git ولا يُرفع للمستودع).

```php
<?php
return [
    'db_host' => 'sqlXXX.infinityfree.com',
    'db_port' => '3306',
    'db_name' => 'if0_XXXXXXXX_lamsa',
    'db_user' => 'if0_XXXXXXXX',
    'db_pass' => 'DB_PASSWORD',
];
```

> عند غياب `config/config.local.php` يستخدم المشروع إعدادات XAMPP المحلية تلقائياً.

## 10. النشر على الإنترنت (ملاحظات)

قبل النشر:

1. غيّر كلمة مرور المدير.
2. اضبط `APP_DEBUG` على `false` (يحدث تلقائياً خارج `localhost`).
3. استخدم مستخدم MySQL بكلمة مرور قوية بدلاً من `root` الفارغ.
4. فعّل HTTPS وحدّث إعدادات الكوكيز إلى `secure`.
5. خذ نسخة احتياطية دورية من قاعدة البيانات ومجلد `uploads/`.
